# 我的 AI 干一半就撂挑子，一篇机器人论文治好了它

**先给结论**：AI 长会话里「干一点就停、交卷特别早」，不是模型变笨了，是**任务进度只存在于上下文里，被反复压缩抹掉**。这个病，一篇机器人论文给了药方，我照着做了一个开源项目。

## 现象：上下文一长，它就撂挑子

用 DeepSeek、Kimi 做长任务，会话稍长一点，任务完成度就往下掉。某家大模型新版本发布后特别明显。我一直以为「上下文太长」是原因，直到翻出自己一个会话的日志。

那个会话叫「抓题更新」，是个中学试卷抓题项目。我把日志解出来一看，数字很硬：

- **378 轮**对话；
- 上下文被压缩 **6 次**，每次约 30 万 token；
- 我说了几十次「继续」——第 189–197 轮**连续 6 次**，第 245–287 轮约 20 次；
- 模型每轮只完成一个子项就交卷，思考里写着 *"turn is long; report partial and stop"*（这轮太长，汇报个部分结果就停）。

关键在最后一句：**它不是以为自己做完了，是知道自己没做完，还是停了。** 进度记不住，只能做一件交一件。

## 一篇机器人论文，点破了这个病

转折来自一篇论文《Is Your Robot's Memory Just a Clock?》（arXiv:2611.14488，2026-11-10）。它研究机器人的记忆：

按时间均匀采样的记忆，会把「暂停/空动作」当成「已完成的工作」。在 RoboMME 的计数任务上，两次 5 秒的暂停，让成功率从 **47/50 掉到 16/50**；把同样的画面从记忆里拿掉，成功率又回来了。

论文给了个扎心的结论：**机器人在数「时钟滴答」，不是在数「做了几件事」。** 删掉时间编码也没用——空动作的画面还占着记忆槽位。有效的修正是「按事件索引」。

## 迁移到 LLM 会话：同一类病

我愣了一下：这不就是我那个会话吗？

机器人的「暂停」= 会话里那些「什么都没推进」的空轮次；机器人的「记忆槽位」= LLM 的上下文窗口。论文说「空事件占槽位、把有用线索挤掉」——我的会话里，是**六次压缩把「继续做完」的进度清单抹掉了**。

病根是同一个：**进度状态放在「易失区」（记忆/上下文），被反复清空。** 模型不是笨，是「记不住做到哪了」。

## 药方：不换大模型，把状态外置

论文还有一句很硬的话：**「在训练里注入暂停没用，反而损害计数。」** 翻译到我的场景——换更大的模型、更大的窗口，只是让「被挤掉」发生得更晚，不是不发生。

真正的药方是论文的结论：**记忆应该数「事件」，不数「时钟滴答」。** 落到 LLM 会话，就是把任务进度外置到磁盘，不靠模型记。

于是我做了一个开源项目 **session-guardian**，两个技能：

1. **session-observer（观察者）**：每个回复前对照衰退特征清单（连续≥3次「继续」、一件就交卷、压缩后失忆、重复不升级、约束漂移），命中就停下。
2. **context-handoff（交接）**：把进度写成一份 HANDOFF.md（从当前真实状态重新生成，永不复用旧文件），给出新会话的开场指令。

一句话：**observer 判断「该不该换」，handoff 负责「怎么无损地换」。** 让便宜模型也能跑长程任务——因为它不再靠「记住」，而是靠「记在盘上」。

## 判断：能做什么，不能做什么

- **能**：衰退时触发交接、无损换会话、便宜模型跑长程；DSH 上还能跑一个确定性脚本扫日志，独立于模型判断。
- **不能**：它不是万能的。Kimi/豆包拿不到本地日志，判断退化靠模型自觉（存在「衰退模型自查衰退」的循环）；几个平台能力还在「需实测」。
- **诚实边界**：交接物不是交接的起点，是交接的产物——切换前一律从当前状态重新生成，永不复用旧文件。

## 你可以立刻做的一件事

如果你也用 DSH，跑一条命令，看看自己会话的「继续」次数：

```bash
node ~/.dsh/skills/session-observer/scripts/check_session.mjs <你的会话>.zstd --threshold 3
```

输出里 `consecutiveContinue` 超过 3，就说明你的会话已经在「效能衰退」了。这不是玄学，是能从日志里数出来的。
