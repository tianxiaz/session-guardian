# 会话效能观察者（session-observer）

**这份文件是平台无关的本体。** 不假设任何平台的钩子/命令/工具名；平台差异在 `adapters/`。
它**复用 `context-handoff`** 产出交接物——observer 只判断"该不该换"，handoff 负责"怎么无损换"。
依赖：需已安装 `context-handoff` 技能（含其 `check_handoff.mjs`）。

---

## 0. 一句话

长会话里模型会「干一点就停、交卷特别早」，而且它自己往往看不见自己在衰退（越衰退越查不出自己衰退）。
本技能做两件事：**① 在衰退特征出现时触发（不靠定时器猜）；② 触发后停下，委托 context-handoff 把任务状态无损搬到下一个干净会话。**

核心信念：**便宜模型跑长程任务的唯一可靠杠杆，是把状态外置到磁盘，而不是靠模型"记住"更多。**
observer 的职责就是——在模型还写得动的时候，把该记的记下来。

---

## 1. 触发契约（谁在什么时候调用本技能）

### 1.1 两条入口

| 入口 | 触发 | 说明 |
|---|---|---|
| **被动观察**（常驻） | 会话出现衰退特征（见 §2） | 靠每轮自检：回复用户前，先对照 §2 清单 |
| **主动一句话（诊断）** | 用户说「观察」/「该换会话吗」 | 分析当前会话是否该换；该换则自动走 §3 三连 |
| **主动一句话（直接交接）** | 用户说「切换」/「交接」 | **跳过判断**，直接走 §3 三连（停下 → 写交接 → 提议切换 + 给开场指令） |

「观察帮助」→ 输出能力卡 + 当前阈值 + 全部可配置项。

一句话分清：「观察」＝先诊断、该换才交接；「切换」＝你已决定要换，直接交接。

### 1.2 每轮自检的时机（现象触发，零定时器）

**每个自然停顿点**（回复用户前、每次准备交卷前）花 1 秒对照 §2 清单。这不是定时器——
用户第 N 次打「继续」这个**现象本身**就是触发信号，模型在自己的输入里看到它，就该检查。

### 1.3 定时器只当"保险丝"

当模型已经退化到"连每轮自检都不做"时，用定时器强制唤醒（平台实现见 `adapters/`）。
**定时器当闹钟，现象当判据。** 不要在定时器到点时"猜"衰退，而是到点就对照 §2 清单。

## 2. 衰退特征清单（判据真源，逐条对）

| # | 现象特征 | 判据（可机械判定） |
|---|---|---|
| 1 | **"继续"循环** | 用户连续 ≥N 轮只说「继续/继续下一步/继续干」（N 默认 3，见 §4） |
| 2 | **一件就交卷** | 一轮只完成一个子项就汇报，且明显还能批量往下做 |
| 3 | **压缩后失忆** | 出现上下文压缩后，重做已完成项 / 漏掉剩余清单 |
| 4 | **重复不升级** | 同一手段连续失败 2 次还在换皮重试（loop capture） |
| 5 | **约束漂移** | 产出开始越过 `boundaries.禁止` / 漏掉早期硬性条件 |
| 6 | **思考暴露** | 思考里出现"这轮太长 / 先汇报部分 / 得停 / we need stop"等放弃信号 |

**命中 ≥1 条（1、2 最优先）⇒ 走 §3 动作。** 命中的判据写进交接物的 `provenance.trigger_detail`。

### 2.1 硬档补充（仅 DSH）：确定性脚本

DSH 上可跑 `scripts/check_session.mjs` 扫本机会话日志，**机械计数**第 1、3 条（连续"继续"次数、
压缩次数、todo 次数、所用模型）。脚本输出不是 LLM 判断，所以**独立于模型的衰退**。命中即触发。

---

## 3. 动作（命中后的三连，严格按序）

```
① 停下推进——不继续换皮重试、不假装继续。
② 委托 context-handoff 写交接：trigger=degradation，在 decisions.尝试过 里写清"试过什么、为什么不行"。
③ 提议切换会话（提议，不阻塞、不自动中止），并给出新会话开场指令（OPENING_PROMPT）。
```

**报告模板**：
```
【效能观察】检测到衰退特征：<第 N 条>（<具体证据>）。
建议在这里交接并换会话。我已把进度写进 <HANDOFF 路径>（已判绿）。
新会话开场指令见 <OPENING_PROMPT 路径>，或直接复制下面这段：
<开场指令全文>
如果你更想在本会话继续，告诉我"继续"即可，我不阻塞。
```

---

## 4. 阈值（可覆盖，跨平台走文本行）

- **默认**：`连续 3 次"继续"` 判衰退。
- **覆盖**：任何会话里说「**阈值：连续 2 次**」即改（本会话生效）。
- **存哪**：协议里一行文本 `threshold: 连续3次继续`。**不依赖配置文件**（豆包云端读不到本地文件）。

---

## 5. 交接物时效校验（防"过期交接物"）

`HANDOFF.md` 是**快照**，不是活状态。**交接物不是交接的起点，而是交接的产物。**

- 真正切换前，**一律从当前真实状态重新生成**（`git rev-parse HEAD` + 最近实际做了什么），
  **永不复用旧文件**；旧文件一律当"未验证"。
- 恢复侧（新会话读 HANDOFF 时）：`updated_utc` 与 `status.恢复检查点` 必须与新会话自己跑的
  `git rev-parse HEAD` 一致；不一致以实测为准、先纠正再干。

## 6. 三平台分档（不假装等价）

| 档 | 平台 | 观察 | 判断 |
|---|---|---|---|
| 硬档 | DSH | 现象→每轮自检 + schedule 心跳 | 确定性脚本扫日志（check_session.mjs） |
| 软档 | Kimi / 豆包 | 现象→每轮自检 + 产品级定时任务 | 模型对照 §2 清单（自觉） |

能力差异是平台决定的，不是本技能偷懒。**交付物里标"需实测"的（Kimi/豆包能否程序化建定时器、
能否读日志）不许当事实承诺。** 详见 `references/platforms.md`。

---

## 7. 自检清单（每次触发后逐条对）

1. 命中的是 §2 第几条？证据写了没？
2. 停下推进了没？有没有还在换皮重试？
3. 交接物是**从当前状态重新生成**的，还是复用了旧文件？
4. `trigger` 写的真实吗？（degradation 就别写成 user-request）
5. 提议是"提议"还是"声称已切换"？（后者是造假）
6. 开场指令给了没？
